![Flutter iOS native assets release의 MinimumOSVersion 검사](https://images.unsplash.com/photo-1551650975-87deedd944c3?auto=format&fit=crop&w=1600&q=80)

이 그림에서 볼 부분은 앱 코드가 아니라 IPA 안에 들어간 프레임워크의 출시 메타데이터다.

Flutter iOS 앱을 올릴 때 `ITMS-90208: Invalid Bundle`과 `MinimumOSVersion` 충돌이 보인다면 `Podfile`만 고쳐서는 부족하다. C++·FFI 플러그인처럼 native assets를 포함한 앱에서 바이너리와 프레임워크 `Info.plist`의 최소 iOS 버전이 달라질 때 생긴다. 순수 Dart 앱에는 해당하지 않는다.

## 오류가 생기는 조건

Flutter 도구가 프레임워크에는 `13.0`을 기록했지만 내부 바이너리가 iOS 14 이상을 요구하면 App Store Connect가 거부한다. Flutter 수정 기록도 이 원인을 설명하며 `targetIOSVersion`을 13에서 15로 바꾸는 변경을 제시한다.

## release 산출물에서 확인한다

코드 서명 전 release 산출물에서 각 프레임워크가 선언한 최소 버전을 확인한다.

```bash
flutter --version
flutter clean
flutter build ios --release --no-codesign

plutil -p build/ios/iphoneos/Runner.app/Frameworks/*.framework/Info.plist \
  | grep MinimumOSVersion
```

`13.0`이 나오면 앱 설정만 보지 말고 해당 프레임워크를 찾는다. `pubspec.lock`의 FFI·native assets 의존성과 `Runner.app/Frameworks` 목록을 대조한다. 디버그 실행 성공은 업로드 검증을 대신하지 못한다.

## 해결 순서

가장 안전한 선택은 native assets 수정이 포함된 Flutter stable 버전으로 올리고 archive를 새로 만드는 것이다. 로컬뿐 아니라 CI의 Flutter 버전도 고정한다.

도구를 바로 바꿀 수 없다면 archive 안의 해당 프레임워크 `Info.plist`를 요구 버전으로 고친 뒤 프레임워크와 앱을 다시 서명해야 한다. plist만 덮어쓰면 서명이 깨진다.

`MinimumOSVersion`을 억지로 13.0으로 낮춰도 호환성이 생기지 않는다. iOS 13 지원이 필요하면 native asset을 교체하거나 낮은 deployment target을 지원하는 버전을 선택한다.

## 출시 전 체크리스트

- [ ] `flutter --version`을 로컬과 CI에서 기록했다.
- [ ] `pubspec.lock`에서 native assets·FFI 의존성을 확인했다.
- [ ] release 산출물의 모든 `MinimumOSVersion`을 확인했다.
- [ ] 앱의 Deployment Target과 프레임워크 요구 버전이 일치한다.
- [ ] 우회 수정 후에는 반드시 재서명하고 `flutter build ipa` 또는 Xcode Validate를 다시 실행한다.

핵심은 `ITMS-90208`을 앱 설정 하나의 문제로 보지 않는 것이다. native framework의 바이너리, `Info.plist`, Flutter 도구 버전을 같은 release 산출물에서 비교해야 한다.
