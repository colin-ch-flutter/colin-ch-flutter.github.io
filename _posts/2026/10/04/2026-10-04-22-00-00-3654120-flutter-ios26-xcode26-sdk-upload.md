이 글의 대상은 Flutter 앱을 App Store Connect에 올리다가 `Unsupported SDK` 또는 Xcode 관련 거절을 만난 팀이다. 2026년 4월 28일부터 Apple은 업로드하는 iOS 앱을 Xcode 26 이상, iOS 26 SDK 이상으로 빌드하도록 요구한다. 다만 `iOS Deployment Target`을 26으로 올리라는 뜻은 아니다. 오래된 iPhone 지원을 유지해야 한다면 배포 타깃은 별도로 낮게 두고, archive를 만든 Xcode와 SDK만 확인하는 편이 맞다.

## 헷갈리는 세 가지 값

| 확인 대상 | 의미 | 출시 판단 |
|---|---|---|
| Xcode 버전 | 빌드 도구 자체 | 26 이상이어야 한다 |
| iOS SDK | archive를 컴파일한 SDK | iOS 26 이상이어야 한다 |
| Deployment Target | 실행 가능한 최소 iOS 버전 | 앱 지원 정책에 맞춰 별도로 결정한다 |

Apple의 기준은 업로드 시점의 Mac에 설치된 Xcode가 아니라, 실제로 생성된 앱이 어느 SDK로 빌드됐는지에 가깝다. 로컬 Xcode를 26으로 바꿔도 CI가 `/Applications/Xcode_25.app`을 선택하면 결과 archive는 그대로 오래된 SDK를 사용한다. Flutter 공식 문서도 iOS 26과 Xcode 26을 지원하며, `flutter build ipa`가 archive와 IPA를 만든다고 안내한다.

## Flutter 프로젝트에서 확인할 순서

아래 명령은 “설치된 Xcode”와 “Flutter가 선택한 Xcode”가 같은지 확인하기 위한 것이다.

```bash
flutter doctor -v
xcode-select -p
xcodebuild -version
xcodebuild -showsdks | grep iphoneos
```

`xcode-select -p`가 `/Applications/Xcode.app/Contents/Developer`를 가리키는지 보고, 버전이 26 이상인지 확인한다. Xcode를 여러 개 설치한 CI라면 빌드 직전에 선택을 고정한다.

```bash
sudo xcode-select --switch /Applications/Xcode.app/Contents/Developer
sudo xcodebuild -runFirstLaunch
flutter clean
flutter pub get
flutter build ipa --release
```

여기서 `flutter clean`은 SDK 선택을 고치는 명령이 아니다. 이전 빌드 산출물이 섞였을 때 원인을 분리하려는 정리 단계다. 실행 권한이 없는 CI에서는 `sudo`를 빼고, 이미지가 이미 Xcode 26을 기본 선택했는지 확인하면 된다.

## archive를 확인해야 하는 이유

빌드 로그에 Xcode 26이 한 번이라도 보였다는 사실만으로는 부족하다. `build/ios/archive`에 생성된 archive를 Xcode Organizer에서 열어 Validate를 실행하거나, CI에서 업로드하는 IPA가 같은 빌드 단계에서 만들어졌는지 확인해야 한다. 로컬에서 만든 IPA를 올렸다고 생각했지만, 실제 업로드 스크립트가 다른 경로의 이전 IPA를 잡는 경우도 있다.

```bash
find build/ios -name '*.ipa' -o -name '*.xcarchive'
xcrun altool --validate-app \
  --type ios \
  -f build/ios/ipa/*.ipa \
  --apiKey "$APP_STORE_API_KEY" \
  --apiIssuer "$APP_STORE_API_ISSUER"
```

검증 결과가 성공해도 App Store Connect 처리 단계에서 다시 경고가 생길 수 있다. 업로드 파일의 Bundle ID, version, build 번호가 의도한 앱과 맞는지 확인하고, Activities의 처리 로그에서 실제 거절 문구를 기준으로 수정한다. 동일한 build 번호로 재업로드할 수 없다는 점도 놓치기 쉽다.

## 실패 조건과 선택 기준

- Xcode 26을 설치했지만 `xcode-select`가 예전 경로를 가리킨다 → CI와 로컬의 선택 경로를 고정한다.
- Xcode는 26이지만 `flutter build ipa`를 실행한 러너가 다른 Mac이다 → 러너의 `flutter doctor -v`와 `xcodebuild -version`을 로그에 남긴다.
- Deployment Target을 26으로 올려 해결하려 한다 → 지원 기기 범위가 줄어드므로 SDK 요구사항과 분리한다.
- Flutter 3.38 미만 프로젝트다 → Flutter를 바로 올리기 전에 플러그인의 iOS 최소 버전과 Pod 설정을 확인하고 별도 브랜치에서 archive를 검증한다.

출시 체크리스트는 다음처럼 짧게 고정할 수 있다.

```text
[ ] 빌드 러너의 xcode-select 경로가 Xcode 26이다
[ ] xcodebuild -showsdks에 iphoneos26.x가 나온다
[ ] flutter build ipa --release가 새 archive를 만들었다
[ ] IPA의 Bundle ID/version/build가 출시 대상과 일치한다
[ ] Validate 결과와 App Store Connect 처리 로그를 확인했다
```

핵심은 iOS 최소 지원 버전을 무리하게 올리는 것이 아니라, 출시 산출물을 만든 Xcode·SDK·CI 경로를 증명하는 것이다. Apple의 SDK 기준과 앱의 Deployment Target은 서로 다른 설정이므로 한쪽을 바꿨다는 이유만으로 다른 문제가 해결됐다고 판단하면 안 된다.
